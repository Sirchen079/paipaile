# 拍拍乐 · 联机派对游戏 设计文档

版本 v0.2 · 2026-08-17 · 状态：已确认（2026-08-17 审定）

---

## 1. 项目概述

- **一句话**：面向玩家的网页联机派对对战游戏——所有人同时秘密出招，回合统一结算，输赢全靠心理博弈。
- **用户**：好友，2~9 人，手机与 PC 双端适配（移动优先）。
- **部署**：自有云服务器，输入访问密码才能进入（密码门），无账号系统。
- **技术路线**（已确认）：自研。Node.js(Express + socket.io) 单进程 + Vue3 + Vite + GSAP。理由：规则高度自定义必须自写逻辑，联机需求轻（回合制事件驱动），特效自由度 100%。

## 2. 已确认的核心规则（2026-08-17 拍板）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 血量 | 建房可自定义，默认每人 1 滴血；被打中一次掉 1 滴，归零淘汰 |
| 2 | V 资源 | 初始 0V，上限 99V，爆V 每次 +1 |
| 3 | 单体招目标 | 必须指定目标（普冲/超冲/一阳指） |
| 4 | 超级盾 vs 究极 | 超级盾可以挡住究极冲击波 |
| 5 | 被取消的招 | 不造成任何效果，V 照扣（白花） |
| 6 | 互相攻击 | 不会互杀：如一阳指对超冲，双方互相抵消、什么都不发生 |
| 7 | 超时不出招 | 自动执行爆V |
| 8 | 胜利条件 | FFA：最后存活者胜；组队：歼灭对方全队 |
| 9 | 人数 | 2~9 人 |
| 10 | 平台 | 手机、PC 都要适配 |

## 3. 完整规则整理（14 招）

### 3.1 招式总表

| 招式 | 消耗 | 类型 | 目标 | 效果 |
|---|---|---|---|---|
| 爆V | 0 | 增益 | 自己 | +1V；被一切伤害招打中（唯一例外：究极打不中爆V） |
| 普通盾 | 0 | 防御 | 自己 | 挡住普通冲击波 |
| 上天 | 0 | 位移 | 自己 | 本回合进入飞天状态 |
| 下地 | 0 | 位移 | 自己 | 本回合进入遁地状态 |
| 普通冲击波 | 1 | 单体攻击 | 选目标 | 伤害；打不中飞天/遁地；被盾挡；对冲被高档克制 |
| 锤天 | 1 | 范围攻击 | 全部飞天者 | 被超冲/究极伤害 |
| 锤地 | 1 | 范围攻击 | 全部遁地者 | 被超冲/究极伤害 |
| 超级盾 | 1 | 防御 | 自己 | 挡住任意冲击波（普/超/究极） |
| 超级冲击波 | 2 | 单体攻击 | 选目标 | 穿透普通盾；可伤锤天/锤地/扭曲虚空者 |
| 锤天锤地 | 2 | 范围攻击 | 全部飞天+遁地+魔爆者 | 被一阳指伤害 |
| 一阳指 | 2 | 单体攻击 | 选目标 | 无视一切盾；可伤锤天锤地者 |
| 魔爆术 | 2 | 反制 | 全部冲击波使用者 | 取消全部冲击波效果并造成伤害 |
| 扭曲虚空 | 2 | 反制 | 全部一阳指使用者 | 取消全部一阳指效果并造成伤害 |
| 究极冲击波 | 3 | 范围攻击 | 见命中表 | 见命中表；打不中爆V者 |

**设计精髓（供 UI/特效强调）**：2V 招形成闭环反制环——
冲击波系 →(被魔爆取消+反伤)→ 魔爆术 →(被锤天锤地打)→ 锤天锤地 →(被一阳指打)→ 一阳指 →(被扭曲虚空取消+反伤)→ 扭曲虚空 →(被超冲/究极打)→ 回到冲击波系。没有无敌招。

### 3.2 回合结算顺序（服务端权威，固定管线）

```
0. 收招校验：存活 / V足够 / 目标合法；超时未出 → 自动爆V
1. V 结算：全员扣消耗；爆V者 +1（上限 99）
2. 状态层：上天/下地 状态本回合生效
3. 取消层：魔爆术 → 全部冲击波（普/超/究极，D2）效果作废
          扭曲虚空 → 全部一阳指效果作废
4. 对冲层：单体招互相指向对方时按"档位 = V消耗"裁定：
          高档命中、低档作废；同档双方互抵（D3）
5. 伤害层：存活招式按 §3.3 命中表结算；所有伤害"同时发生"
          （先算完全部命中，再统一扣血 → 天然杜绝先后手救人）
6. 淘汰结算与胜负判定（FFA 存活≤1 / 组队全灭）
```

### 3.3 受击判定总表（引擎与单测的蓝图）

**判定模型**：每回合每人只出一招 = 摆一个"架势"。招式描述中明示了"自身会被 X 伤害"的（锤天/锤地/锤天锤地/一阳指/魔爆/扭曲虚空），**只有**那些来源加上对冲规则能伤到他；未明示的（爆V/普盾/超盾/上天/下地/普冲/超冲）可被一切"够得着"的伤害命中。

| 攻击招式 | 能命中 | 打不中 / 无效 |
|---|---|---|
| 普通冲击波 | 爆V者；普冲/超冲使用者（对冲判定后） | 飞天/遁地；普盾、超盾被挡；锤天/锤地/锤天锤地/一阳指/魔爆/扭曲虚空/究极使用者（架势免疫）；被魔爆取消 |
| 超级冲击波 | 爆V者；普盾者（穿透）；普冲/超冲者；锤天者；锤地者；扭曲虚空者 | 飞天/遁地（D1）；超盾被挡；锤天锤地/一阳指/魔爆/究极使用者；被魔爆取消 |
| 一阳指 | 爆V者；普盾者、超盾者（无视盾）；普冲/超冲/一阳指者（对冲后）；锤天锤地者 | 飞天/遁地（D1）；锤天/锤地/魔爆/扭曲虚空/究极使用者；被扭曲虚空取消 |
| 锤天 | 全部飞天者 | 其余 |
| 锤地 | 全部遁地者 | 其余 |
| 锤天锤地 | 全部飞天者 + 全部遁地者 + 全部魔爆者 | 其余 |
| 魔爆术 | 全部冲击波使用者（普/超/究极，D2），并取消其效果 | 其余 |
| 扭曲虚空 | 全部一阳指使用者，并取消其效果 | 其余 |
| 究极冲击波 | 全部：飞天/遁地/锤天/锤地/普冲/超冲/普盾/扭曲虚空 使用者 | 爆V者（明示打不中）；超盾者（已确认挡住）；锤天锤地/一阳指/魔爆/究极使用者（D4） |

### 3.4 裁定清单（已审定）

| # | 问题 | 最终裁定 |
|---|---|---|
| D1 | 飞天/遁地能躲什么？ | **躲一切单体攻击**（普冲/超冲/一阳指都打不中），只有锤天/锤地/锤天锤地/究极打得中 |
| D2 | 魔爆术 vs 究极冲击波？ | **取消究极并伤害其使用者**（2V 反制 3V，闭环成立） |
| D3 | 对冲细则 | 按 V 档位：高档命中、低档作废；同档互抵；究极是范围招不参与对冲 |
| D4 | 究极使用者的克星 | 只有魔爆（对冲无更高档） |
| D5 | 组队模式友军伤害 | **建房时可开关，默认关闭**。关闭时：单体招不能选队友为目标，范围招自动跳过队友 |
| D6 | 前端框架 | Vue 3 + Vite + TS + GSAP |

### 3.5 房间配置项（建房时设定）

- 血量：默认 1，范围 1~10
- 出招倒计时：默认 15 秒（可选 10/15/20/30）
- 模式：FFA（默认）/ 组队（迭代二上线）
- 友伤开关：默认关闭（组队模式生效；见 D5）
- 表演回放时长：服务端按事件数动态定（2s + 0.6s×事件数，上限 8s）

## 4. 系统架构

```
浏览器（Vue3 + GSAP，手机/PC 自适应）
   │  HTTPS 登录页：输入访问密码 → HMAC 签名 httpOnly Cookie
   ▼
Nginx（TLS 终结 / 静态文件 / WebSocket 升级）
   ▼
Node 单进程
 ├── Express：密码中间件（护静态 + API）
 ├── socket.io：房间管理 / 回合状态机
 └── 结算引擎 shared/engine.ts：纯函数 (players, moves) → {events, nextState}
```

- **服务端权威**：客户端只提交意图，一切判定在服务端；动画只按事件流回放。
- **无数据库**：房间全内存，进程重启即清空（轻量场景可接受）。
- **目录结构**：`server/`（入口+房间+协议）、`shared/`（类型+结算引擎+单测）、`web/`（前端）。

## 5. 通信协议（socket.io 事件）

| 方向 | 事件 | 载荷 | 说明 |
|---|---|---|---|
| HTTP | POST /api/login | {password} | 成功签发 httpOnly Cookie |
| C→S | room:create | {nickname, avatar} | 返回 4 位房间码 |
| C→S | room:join | {code, nickname, avatar} | |
| C→S | room:config | {hp, pickSeconds, mode} | 仅房主 |
| C→S | game:start | — | 仅房主，≥2 人 |
| C→S | game:submit | {moveId, targetId?} | 出招 |
| C→S | room:leave | — | |
| S→C | room:state | 全量快照 | 进房/重连/变化时同步 |
| S→C | game:phase | {phase, round, deadline} | pick / show |
| S→C | pick:progress | {playerId} | 谁已出招（不泄露内容） |
| S→C | round:result | {round, events[], standings} | **核心**：结算+动画编排 |
| S→C | game:end | {winners, standings} | |

**round:result 的 events 事件流**（前端按序播放动画）：
`reveal{p,move,target}` → `vChange{p,delta}` → `state{p,上天|下地}` → `cancel{by,targets}` → `clash{a,b,winner}` → `hit{src,dst,move,lethal}` → `blocked{src,dst,by}` → `miss{src,dst,reason}` → `death{p}` → `roundEnd`

## 6. 回合状态机

```
LOBBY → PICK(倒计时) → RESOLVE(服务端纯函数,瞬时) → SHOW(回放动画)
  ▲                                                      │
  └────── END(胜负结算) ◄── 存活≤1(或全灭) ◄── 循环 ←──┘
```

- 超时未出招 → 自动爆V；掉线者座位保留到局末，重连发全量快照恢复。
- 出招面板：V 不足的招置灰；单体招先点目标再确认。

## 7. 前端设计与特效分镜（打击感是一级需求）

**布局（移动优先）**：顶部玩家卡横排（头像 / HP 心 / V 计量 / 状态图标 / 已出招标记），中央舞台（事件动画演出），底部出招面板（按 0V/1V/2V/3V 四档分组，大按钮，拇指可达）。

**事件 → 分镜表（一期基线，GSAP timeline + canvas 粒子层）**：

| 事件 | 分镜 |
|---|---|
| reveal | 全场定格 0.4s，出招者卡牌翻转+招式横幅+图标冲屏 |
| 爆V | 金色光柱冲天 + V 字飞入计量条 |
| 盾 | 普盾蓝色六边形展开 / 超盾金色展开+波纹 |
| 上天/下地 | 角色卡升空悬浮 / 下沉半透明 |
| 冲击波 | 扇形冲击环从出招者扩散到目标；超冲紫色电弧缠绕；究极全屏红黑冲击波 |
| 锤天/锤地 | 巨锤从天砸落 / 地面裂开岩刺，命中者集体受击 |
| hit | 目标闪白 1 帧 + 击退抖动 + 伤害数字弹跳 + **屏幕震动（3 级强度）+ 命中停顿 60~100ms（hit-stop）**+ 粒子迸溅 |
| blocked | 盾面涟漪 + 格挡火花四溅 |
| cancel | 黑紫裂纹撕裂招式图标 |
| miss | 目标残影闪避 / 钻地灰尘 |
| death | 角色卡灰化碎裂坠落 |
| 胜利 | 聚光灯 + 定格 + 彩带雨 |

**打击感三件套**：hit-stop（命中瞬间全局暂停几十毫秒）、screen shake（分强度）、hit-flash（闪白）。这是"爽"的核心，优先级高于华丽度。
音效（迭代二）：Howler + 免费素材包，出招/命中/格挡/胜负各一套。

## 9. 部署方案

- 云服务器 Linux：`docker-compose`（app 容器 + nginx 容器）或裸机 pm2 + 系统 nginx。
- TLS：有域名走 Let's Encrypt；无域名临时 `http://IP:端口` 也可跑。
- 密码门实现：登录页 POST 校验 → HMAC 签名 httpOnly Cookie → Express 中间件 + `io.use()` 握手双重校验（手机上体验比浏览器原生 basic-auth 弹窗好）。
- 访问密码从环境变量注入，改密码无需改代码。

## 10. 测试方案

- **结算引擎单测**（重点）：§3.3 判定表逐格用例 + 对冲三角（A→B、B→C、C→A）+ 取消链（魔爆 vs 究极）+ 边界（99V 上限、超时自动爆V、同档互抵、多人同亡平局）。
- 手动 e2e：多浏览器标签页 + 手机真机联调。
- M2 补 headless 多客户端模拟脚本做压力与回归。
